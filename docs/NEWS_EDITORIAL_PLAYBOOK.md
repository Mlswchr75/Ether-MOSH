# Ether-MOSH News + Updates editorial playbook

## Purpose

Publish discoverable, shareable effect education that is technically useful first and funny second. Fictional incidents may carry the story; effect behavior, history, settings, product facts, and production advice must be real and sourced.

## Required article anatomy

1. Urgent, active, slightly suggestive title centered on one current Ether-MOSH effect.
2. Search description, 5–8 specific keywords, canonical URL, 16:9 original hero image, and truthful image alt text.
3. A 40–70 word direct answer that defines the effect and names its key controls.
4. Clear satire disclosure separating invented characters/events from researched facts.
5. Short fictional dispatch, then a sourced technical/history explanation.
6. Five-step Ether-MOSH tutorial using current category, control names, and defensible starting values.
7. Parameter table and at least four uses spanning print, pattern, vector/Lottie/motion, projection/venue, museum, installation, or education where relevant.
8. Downloadable field card or recipe data.
9. Four visible natural-language FAQs with concise direct answers.
10. Authoritative source links and links into `/effects`, `/edit`, and related stories.
11. One verified live product from `aestheticrebellion.store`, introduced as unmistakably shameless sarcastic product placement.

## SEO + AEO release gate

- Use one primary query naturally in the title, H1, description, opening answer, one H2, image alt text, and URL only when readable.
- Answer user intent immediately; do not pad the answer box.
- Emit BlogPosting, FAQPage, HowTo, and breadcrumb structured data where applicable.
- Generate route-specific static HTML metadata so social bots and non-JavaScript crawlers see the canonical title, description, image, and structured data.
- Add the canonical URL to the sitemap and RSS feed, link it from the News index, and link related effects/articles.
- Never keyword-stuff, fabricate expertise, plagiarize, fake a guest, or promise virality. Optimize for usefulness, clarity, novelty, and shareability.
- Verify every external product page and research source on publication day.

## Daily workflow

Inspect the current effect registry, choose an effect not yet covered, research primary/authoritative sources, verify controls against code, write and label the satire, make original editorial art, update the content source/RSS/sitemap/download, run typecheck/build/tests, review desktop and mobile in a real browser, then publish only when all checks pass.
